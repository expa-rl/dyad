# EARL：论文到 project page 的内容取舍

调研日期：2026-10-16。本记录先核对原页面和论文，再提出编辑判断；“为什么这样组织”是分析，不代表作者公开说明过设计意图。

来源：

- [EARL project page](https://expa-rl.github.io/)：核对页面正文、HTML 结构，以及桌面端实际呈现。
- [EARL 论文 v2，2025-10-17](https://arxiv.org/html/2510.07581v2)；[PDF](https://arxiv.org/pdf/2510.07581v2)：重点对照 §3–5、附录 H–J。以下图表编号均指这个固定版本。
- Dyad 的后续选择另见 [Dyad 页面重构方案](dyad-project-page-plan.md)。

## 1. 结论

EARL 页面围绕三个希望读者记住的能力组织内容，再用 Approach 解释机制。它没有按论文实验目录逐项展示，也没有给每个结论配一张完整结果表。

最值得迁移的是三件事：先讲问题和价值；给每个价值选择足够的证据；把实现机制集中放在后面的 Approach。内容详略取决于解释的需要，不要求每节等长、每节都有图，或覆盖所有实验。

## 2. 页面实际展示了什么

| 顺序 | 页面内容 | 对应论文依据 | 页面的选择 |
|---|---|---|---|
| 首屏 | 题目、作者、机构、代码与论文入口 | 论文身份与资源 | 直接使用学术项目页的标准首屏 |
| TL;DR 与动机 | 一句话概括，再解释用文本兼任推理与环境控制的问题，引出 ExpA | 摘要、§1、§3 | 给出最低限度的概念说明，把完整机制留到后面 |
| 1. Multi-turn Contingent Planning | 解释为什么 Countdown 需要根据中间反馈调整策略；展示 3B/7B 成绩图和规划短语统计表 | §5.1–5.2、Table 2 的 Countdown 部分、附录 I.1 的 Table 8 | 从四项 Calc-Bench 任务中挑出一个最能解释主张的任务，再补一类行为证据 |
| 2. Partially Observed Environment | 先解释部分可观测的问题，再介绍隐藏数字的 compare/swap 排序；给出 Sort-4 达到满分与约 70 步训练的结论，配一个过程视频 | §3 的交互定义、§5.3；相关证据包括 Figure 6、Table 5 和排序分析 | 用具体交互过程降低理解成本，没有搬入完整排序评测图表 |
| 3. Readiness for Zero-RL | 一段话说明 CPO 支持从 base model 开始 RL，不依赖监督工具调用示例与文本格式 | §4.2、§5.2 的消融、Table 4 | 这是一个短的训练能力声明，没有独立结果图表 |
| Approach | 简短说明目标，再按传统文本交互、ExpA 交互、反事实探索三个环节解释，每个环节配动画和文字 | §1、§3、§4 | 重新组织成可理解的过程，没有复刻公式、伪代码和优化推导 |
| 结尾 | BibTeX、模板署名与许可 | 论文与网站资源信息 | 为进一步阅读和复用提供入口 |

关键核对：网页规划短语表的总次数与附录 Table 8 相同，并不是正文 Table 3 的“每条 rollout 平均次数”。网页 Countdown 图只展示完整 Calc-Bench 评估中的一个任务；页面图注也明确说明，训练使用多任务数据。不能把这张图解读成单独只训练 Countdown 的结果。[论文 pp.6–8、29–30](https://arxiv.org/pdf/2510.07581v2#page=6)

## 3. 论文中哪些内容没有完整进入页面

这里区分“结论有提到”和“完整证据被展示”。例如，页面提到排序效率，但没有展示效率对照表。

| 论文内容 | 页面处理 | 对内容取舍的启发 |
|---|---|---|
| Calc-Bench 的 Arithmetic、Count、GSM8K*，以及完整综合成绩，Table 2 | 不展示完整表；重点只放 Countdown | 同属主实验的任务，也可以只选择最能解释核心能力的一项 |
| Countdown 的交互数、幻觉数、平均规划短语数，Table 3 | 未直接展示；改用附录的具体短语统计 | 选择更容易被读者理解的行为证据，而非按正文优先级机械搬运 |
| GSM8K* 正确轨迹的响应长度分布，Figure 4 | 未展示 | 相关收益不一定需要在首页另开章节 |
| CPO/GRPO、base/instruct、有无环境 prompt 的完整消融，Table 4；训练曲线，Figure 5 | Zero-RL 节只提炼一段结论 | 一个能力可以被介绍，而把细致归因留给论文 |
| Sort-4/Sort-5 按最少交换次数分层的准确率，Figure 6 | 未展示完整图；突出 Sort-4 结论和过程视频 | 让读者先理解“发生了什么”，无需先读完整评测矩阵 |
| 排序的交换/比较次数对照，Table 5；算法伪代码、决策树 | 文字提到算法效率，具体表格和算法留在论文 | 描述结果和展示全部论证是两种不同层次 |
| 0.5B 的 Arithmetic OOD 实验，Figure 7；多任务训练曲线，Figure 8 | 未展示 | 模型规模覆盖与训练过程不必占用主阅读路径 |
| 环境配置消融，Table 7；初始化分析，Figure 10；长轨迹案例 | 未完整展示 | 鲁棒性、实现选择、长案例作为论文里的深入证据 |
| 数学定义、更新规则、超参数、数据构造、prompt | 只保留机制所需的解释 | 页面承担研究介绍，详细复现信息由论文和代码承担 |

依据：[论文 §5，pp.6–9](https://arxiv.org/pdf/2510.07581v2#page=6)、[附录 H–J，pp.27–33](https://arxiv.org/pdf/2510.07581v2#page=27)，逐项与[页面](https://expa-rl.github.io/)对照。

## 4. 为什么这些选择能够形成主线

**第一节先给可理解的收益，再给行为解释。** Countdown 的成绩回答“效果如何”；规划短语表补充“行为有什么变化”。二者服务同一个论点，不是两个并列的实验章节。需要保持证据边界：短语出现次数是行为线索，单凭它不能证明模型具有完整的规划能力。

**第二节用过程说明抽象能力。** “部分可观测”先被解释成一个具体困难，再通过隐藏数字的比较和交换变得可理解。视频承担解释过程的工作。这一点可以迁移到架构动画，不要求 Dyad 也制作一个真实任务回放。

**第三节允许简短。** Zero-RL 是一个独立、值得记住的训练属性，页面用一段话说明即可。EARL 没有为了让三节形式对称而塞进消融表。

**Approach 回答前面的收益从何而来。** 动画按“现有接口的问题 → 改变后的接口 → 怎样学会使用它”排列。论文里的机制被转换成阅读顺序，而不是压缩成一张密集架构图。

以上是根据页面组织作出的编辑判断，没有页面访问数据或读者实验来证明它比其他方案更有效。

## 5. 标题与排版：哪些可以直接沿用

三个编号主节都只有一个大标题，随后直接进入段落。没有“小号类别标签 + 另一个宣传式大标题”的组合。这个结构应直接用于 Dyad。

页面主节的基本骨架是：

```html
<section class="section">
  <div class="container is-max-desktop">
    <h2 class="title is-3">2. …</h2>
    <p>为什么这个问题重要、我们做了什么、观察到了什么。</p>
    <!-- 仅放支持本节论点的图、表或视频 -->
  </div>
</section>
```

可以直接复用：

- 居中的题目、作者、机构和资源按钮。
- 浅灰背景的 TL;DR 与动机区；两者放在同一个开场区域。
- 三个编号主节的单列阅读结构：标题、段落、证据，使用同一内容容器。
- Approach 的浅灰背景和图文解释方式；视频足够清晰时，也可以独占一行。
- BibTeX、按钮、页脚和应保留的模板署名。

本次在 1280px 宽的桌面视口中检查，主容器为 960px，主节标题为 32px，主要解释段落为 19.2px，行高为 30.72px（1.6 倍）。这比当前 Dyad 的窄文字列、宽图表列和多个左右拆分布局更一致。它们是布局参考，不是必须逐像素照抄的要求。

有一个需要准确区分的细节：EARL 的 Approach 内部存在较小的机制说明标题，HTML 中也用到了 h2；因此不能说整站完全没有局部标题。应沿用的是三个编号主节的平面结构，以及每个标题只承担一次命名的原则。Dyad 的 Approach 只有一个 MP4 时，没有必要再加一套重复标题。

另一个不沿用的细节：EARL 本身使用了页面内 Figure/Table 编号和链接。根据当前用户要求，Dyad 正文不使用“paper / Figure 1 / Table 3”式引用；证据用自然语言图注解释，详细来源保存在研究记录与数据文件中。

## 6. 对 Dyad 的直接约束

1. 主节围绕读者应记住的价值，而非按实验类型罗列。
2. 一节先确定一个论点，再选证据；不能先决定把所有表放进来，再补文字。
3. 图表可以选择明确标注范围的子集，但不能隐藏该子集中的负向结果，或把局部结果写成普遍保证。
4. 不要求把 EARL 的 Countdown、排序、Zero-RL 三个主题对应搬到 Dyad；尤其不能把 EARL 的 Zero-RL 声明移植给需要监督对齐的 Dyad。
5. 解释性文字要说明动机、设置和含义，不以追求相同字数为目标。
6. 主节采用一个编号 h2；Approach 采用一个 h2。去掉当前 Dyad 的 section-label 与重复大标题组合。
7. 完整实验、消融、训练细节默认留在论文；不再用一串折叠区把整份论文移到首页。

这些判断落实后的内容范围、具体图表选择和英文草稿见 [Dyad 页面重构方案](dyad-project-page-plan.md)。
